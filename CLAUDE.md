# CLAUDE.md

## Project Overview

This is a **public GitHub repository** (published as ml-theses.org) providing guidance to thesis students supervised by Alex Jung (Associate Professor for Machine Learning). It covers **all thesis levels** (bachelor's `BSc`, master's `MSc`, doctoral `PhD`) and is **independent of the host university**: students currently come from Aalto University (Finland) and IMC Krems University of Applied Sciences (Austria); earlier theses were at TU Wien. The audience is current and prospective supervisees. The GitHub repository is `alexjungaalto/mlthesis` (renamed from `masterthesis` in October 2026; the old URL redirects).

## Repository Structure

- `README.md` — Main guide: supervisor/student expectations, thesis levels, getting started, timeline, writing conventions, evaluation process, and a **University-Specific Information** section (one subsection per university: Aalto, IMC Krems). Keep the general sections university-neutral; anything that depends on a university's rules goes into its subsection.
- `Garage.md` — The weekly online Thesis Garage (open to all levels and universities)
- `topics.csv` — **Source of truth** for available thesis topic proposals. Hand-edit this file.
- `compile_topics.py` — Python script to compile and filter the topic catalog
- `Topics.md` — **Auto-generated** from `topics.csv` via `compile_topics.py` (do not edit directly)
- `theses.csv` — **Source of truth** for all supervised theses, every level and university (Aalto, IMC Krems, TU Wien). Hand-edit this file.
- `compile_theses.py` — Python script to compile, filter, and export the thesis list
- `theses.md` — **Auto-generated** from `theses.csv` via `compile_theses.py` (do not edit directly)
- `material/` — PDFs and templates (grade characterization, self-assessment form, peer-review forms)
- `material/creategraphtex.py` — Utility to extract LaTeX document structure as a graph
- `mkdocs.yml`, `build_site.sh`, `requirements-docs.txt` — Static website (ml-theses.org) build config; see `DEPLOY.md`
- `topics/<slug>/` — Optional full proposal for a topic (`proposal.tex`, `references.bib`, `proposal.pdf`). The PDF is published to the website and linked from the catalog via the topic's `url`.
- `docs/`, `site/` — **Generated** by `build_site.sh` (git-ignored build artifacts; never edit by hand). `docs/` is the assembled MkDocs input; `site/` is the final static website.

## Key Conventions

- **Audience**: All content is student-facing. Write clearly, accessibly, and actionably.
- **Level- and university-neutral by default**: do not write "master's thesis" where "thesis" is meant, and do not assume Aalto rules, services, or links in general sections. University-specific facts (regulations, forms, templates, AI policies, libraries, appeal deadlines) belong in the README's University-Specific Information section; cite the official document (and section number) they come from. IMC Krems is a university of applied sciences and has no doctoral programmes.
- **Terminology**: Use the [Aalto Dictionary of ML](https://aaltodictionaryofml.github.io/) for ML terms.
- **References**: Format citations per IEEE guidelines.
- **AI disclosure**: AI tool usage disclosures go in a dedicated statement, NOT in the Methods section (which is reserved for research methods).
- **No sensitive content**: This is a public repo. Do not add internal notes, credentials, or draft-quality content.

## Working with the Thesis List

- **`theses.csv` is the only file to hand-edit.** Columns: `number, author, title, university, level, status, date, industry, url, recording, task_id`.
- `university` is a short key (`Aalto`, `IMC Krems`, `TU Wien`); `compile_theses.py` maps it to the full name via `UNI_DISPLAY` — add new universities there. `level` is `BSc`, `MSc`, or `PhD` (empty means `MSc`); `compile_theses.py` rejects anything else. `task_id` is the Aalto thesis-task identifier (optional, internal bookkeeping).
- `recording` is an optional YouTube link to the thesis presentation (from Alex Jung's channel). Leave blank when no recording exists; verify the URL points to the correct student's talk before adding it.
- `theses.md` is a **build artifact** generated by `compile_theses.py`. Never edit it directly — changes will be overwritten on the next run.
- After any edit to `theses.csv`, regenerate it:
  ```
  python compile_theses.py --markdown
  ```
- For a standalone LaTeX/PDF export of the thesis list, run `python compile_theses.py --tex`. The resulting `theses.tex` (and a compiled `theses.pdf`) are git-ignored local exports — do not commit them.
- Run `python compile_theses.py --stats` for summary statistics (per university, level, year, industry partner). Filter with `--university`, `--level`, `--status`, `--year`, `--industry`.
- When adding new theses, append to `theses.csv` and re-run the script.
- The thesis list also feeds the **alexjung.at supervision page**: `build_site.sh` runs `python compile_theses.py --supervision <path>` against the Jekyll checkout at `~/MachineLearningForAll.github.io/supervision.md` (override with `ALEXJUNG_SITE_DIR`; skipped if absent, e.g. in CI). Only the marker-delimited section of that page is regenerated; commit and push in that repo to publish.
- Ground truth for author names and titles is the `citation_author` / `citation_title` metadata on the linked Aaltodoc record. Use proper diacritics (e.g. `Hämmäinen`, not `Hamminen`).

## Working with Topic Proposals

- **`topics.csv` is the only file to hand-edit.** Columns: `id, title, area, data_source, difficulty, level, status, description, url, references`.
- `level` lists the thesis levels a topic suits, separated by `/` (e.g. `BSc/MSc`, `MSc/PhD`); empty means all levels. The catalog renders it as **Level:** and `--level BSc` filters on it.
- `references` is an optional bibliography: one or more entries separated by ` | `, each formatted per IEEE guidelines. They render as a numbered **References** list under the topic.
- `Topics.md` is a **build artifact** generated by `compile_topics.py`. Never edit it directly — changes will be overwritten on the next run.
- After any edit to `topics.csv`, regenerate the catalog:
  ```
  python compile_topics.py --markdown
  ```
- `status` is `open` or `taken`. The published catalog lists only `open` topics by default; use `--all` to include taken ones.
- Each topic is one short CSV row. Keep `description` to a concise paragraph.
- For a topic with a full written proposal, store its source and PDF in `topics/<slug>/` (`proposal.tex`, `references.bib`, `proposal.pdf`) and set the row's `url` to `topics/<slug>/proposal.pdf`. The catalog renders this as a "Read the full proposal" link, and `build_site.sh` publishes the PDF at the same relative path (so the link works both on the website and in the GitHub view of `Topics.md`).

## Style Notes

- Do not use emojis in README.md or the topic catalog.
- Keep markdown well-structured with a table of contents for long documents.
- Link to Aalto's official policies (responsible AI use, academic appeals) rather than paraphrasing them extensively.
